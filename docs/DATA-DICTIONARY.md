# 积分规则

会员号、事件号和消费引用均为字符串，前导零保留。积分必须正整数，使用Decimal校验后转为整数，不支持小数积分。事件时刻有时区偏移，统一UTC。规则有效窗与积分可用期均为半开区间。
同一时刻先发放，再消费，最后退款；同类按事件编号排序。消费批次按最早到期、最早发放、批次编号依次选择，余额不足时整笔失败。批次在到期时刻立即不可用，不能消费未来发放积分。
退款必须引用同一会员已成功消费，累计退款不得超过原消费。部分退款按原分配的逆序回拨，先回拨最后消耗的批次；未到期恢复，已到期只记过期退款，绝不复活。后续消费使用回拨后的可用余额。
发放积分=可用积分+已消费积分−全部已退款积分+自然到期积分+过期退款积分。已退款包括有效恢复与过期不恢复。失败消费与失败退款均不改余额，移入隔离。
退货补偿按退款回拨明细逐源批次生成，批号 `C-<退款事件>-<原批次>`，同输入与规则版本稳定且唯一。补偿额不超过退款额，累计补偿不超过原消费的未退部分（原消费额减累计已退）。到期裁决有两个闸门：`same_day_consumption`（门店当天可消费）与 `finance_liability_ack`（财务可解释新增负债）同时为真才按退货时刻重算可用期（默认窗口30天，可由 `window_days` 配置），该模式产生等额新增负债；任一为假则沿用原批次到期时刻，已到期部分记原批次到期损失、批次永久关闭，不复活也不延长积分责任，且新增负债必须为零。补偿自检含超额（COMPENSATION_OVER_REFUND）、虚增负债（LIABILITY_EXTENDED）与未退上限（COMPENSATION_CAP）。
发布是独立于账本的显式动作：`POST /api/runs/{run_id}/compensations/publish` 携带当前 `revision`，先过补偿自检与积分/行守恒，再在单事务内写入；核对失败或版本陈旧整体回滚，旧版余额保留，重复执行只返回重复批号不新增、不改版本。已关闭批次不可发布。发布状态在批次读取时合并进补偿行（待发布/已发布/已关闭）。
期末时点默认2026-11-03T00:00:00+08:00，未来事件隔离。示例会员00001：100+80发放，消费120，退款30，其中20恢复、10过期；再消费50后剩余30。
